# E05: доступ к съёмному носителю

**Дата:** 20 ноября 2026 года. **Узлы:** pc1 и pc2, домен `lab.test`. **Статус:** исходный доступ, отказ при включённом запрете и восстановление доступа подтверждены на обоих клиентах. Вместе с [проверкой обоев](e05-desktop-wallpaper.md) это закрывает E05.

## Вопрос и исходные условия

Можно ли через одну компьютерную GPO запретить монтирование съёмного носителя в обычных доменных сеансах на двух рабочих станциях ALT Linux и затем вернуть доступ?

На dc1 восстановлены внешний DNS и синхронизация времени. Оба клиента выбрали dc1 (`10.77.0.10`); у `student2` подтверждены новые графические входы, UID `1164001106`, группа `lab-students` и свежие TGT для `student2@LAB.TEST`. На pc1 имя в сеансе короткое, на pc2 — полное. [Выводы проверки времени и входа](../evidence/20-11-2026/clients-time-and-student2.txt).

Один физический USB-накопитель передавался через VirtualBox по очереди в pc1 и pc2. На обоих `lsblk` определяет его как `sdb` с транспортом `usb`; раздел `sdb1` — exFAT, 58,6G. В «Файлах» этот же том подписан «Том 63 Гб». Для чтения использован `e05-test.txt` со строкой `E05 USB test`; исходные проверки монтирования сделаны под обычной доменной учётной записью.

## Метод и ожидаемый результат

1. В сеансе `student2` подключить носитель, открыть том в «Файлах» и записать исходную точку монтирования. Подтвердить, что тестовый файл находится на носителе и доступен. Перед передачей между ВМ извлечь носитель из текущей ВМ.
2. На pc1 из сеанса администратора домена через ADMC настроить отдельную GPO `E05-Lab-USB` для OU `Lab-Computers`. Эта OU содержит PC1 и PC2; параллельную GPO обоев `E05-Lab-Desktop` менять не требуется.
3. В GPUI открыть **Компьютер → Административные шаблоны → Система → Доступ к съёмным запоминающим устройствам**. Включить параметр **«Съёмные запоминающие устройства всех классов: Запретить любой доступ»** и сохранить. Это параметр Microsoft `Deny_All`; на ALT он применяется через Polkit [1, 2].
4. Пока носитель извлечён, на каждом клиенте под root обновить компьютерные политики. Снова войти под `student2`, подключить тот же носитель и попробовать открыть том. Устройство должно определиться, а попытка монтирования обычным пользователем — завершиться отказом.
5. В той же GPO установить этому параметру **«Отключено»**, сохранить, снова обновить политики. Повторить подключение и открытие файла на двух клиентах. Ожидаются восстановленная точка монтирования и чтение той же строки.

Команды администратора на каждом клиенте после каждого изменения:

```bash
gpupdate --target Computer --force
echo "gpupdate exit code: $?"
```

Команды измерения из сеанса `student2`:

```bash
hostname -f
lsblk -o NAME,TRAN,SIZE,FSTYPE,LABEL,MOUNTPOINTS
```

На обоих клиентах при включённом запрете дополнительно выполнена попытка `udisksctl mount -b /dev/sdb1` без повышения прав. Имя `sdb1` относится к этому запуску; при повторении сначала сверить раздел по `lsblk`.

## Настройка политики и фактический результат

При первом поиске на показанных кадрах GPUI видны локальные ветки шаблонов, в том числе «Система ALT», но не нужная ветка Microsoft «Система». Проверка на pc1 вернула `/usr/share/PolicyDefinitions/RemovableStorage.admx` и локализации `en-US` и `ru-ru`. Пользователь нашёл параметр и сохранил его; конкретное действие, после которого он появился, не зафиксировано. Новая установка шаблонов результатами не подтверждена. ## Итоговое состояние и границы

Компьютерная GPO дала одинаковый результат на обоих клиентах: при включённом запрете накопитель обнаруживался, однако его нельзя было смонтировать через «Файлы» и UDisks2 из сеанса `student2`. После отключения параметра доступ вернулся. Предмет проверки — одна флешка, одна доменная учётная запись и два клиента. Опыт не проверяет физическое отключение USB, другие типы носителей, доступ к уже смонтированному разделу, запрет записи отдельно, действия root или эффект удаления GPO.

Финальный параметр в `E05-Lab-USB` — **«Отключено»**. Пользователь подтвердил итоговые снимки `after-e05-usb-2026-11-20` для dc1, pc1 и pc2. Восстановление из них не проводилось; [сведения о снимках](../evidence/20-11-2026/vm-snapshots.txt).
