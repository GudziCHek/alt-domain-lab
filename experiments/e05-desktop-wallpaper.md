# E05: общий фон рабочего стола и запрет его изменения

**Дата:** 10 октября 2026 года. **Узлы:** pc1 и pc2, домен lab.test. **Статус:** часть E05 с обоями выполнена успешно на обоих клиентах; съёмные носители ещё не проверены.

## Вопрос

Можно ли через ADMC и GPUI задать одинаковый фон на двух клиентах ALT Workstation, запретить пользователю менять его и затем централизованно снять запрет?

## Исходные условия

dc1 работает, оба клиента подключены через SSSD. На pc1 используются короткие доменные имена, на pc2 после E09 — полные. В новых сеансах student2 подтверждены UID 1164001106, GID 1164000513, lab-students с GID 1164001107, обычные локальные группы и HOME=/home/LAB.TEST/student2.

-----------------------------------|----------------------------------------------------------------
ADMC на pc1                        | 0.24.0-alt1.x86_64
GPUI на pc1                        | 0.2.55-alt1.x86_64; /usr/bin/gpui-main
gpupdate на pc1 и pc2              | 0.16.1-alt1.noarch

gpupdate-setup, оба клиента        | enabled; workstation; samba

Снимки before-e05-2026-10-10 выполнены до изменений и прямо подтверждены пользователем.

## Метод и критерии

1. Создать OU Lab-Computers и переместить туда только PC1 и PC2; DC1 оставить в Domain Controllers.
2. Создать E05-Lab-Desktop и связать её с Lab-Computers.
3. В компьютерной части GPUI задать оба пути к фоновой картинке без блокировок.
4. Обновить компьютерные политики и проверить значения ключей и фон в сеансах student2 на обоих клиентах.
5. Изменить фон пользователем на Эльбрус: без блокировки запись должна разрешаться.
6. Включить обе блокировки в той же политике, обновить её и проверить новые сеансы после перезагрузки клиентов.
7. Попытаться изменить оба ключа: ожидаются writable=false и отказ записи.
8. Снять обе блокировки, обновить политику, перезагрузить клиентов, проверить writable=true и успешную запись обеих тем.

Вывод gpupdate с кодом 0 оценивается вместе с результатами gsettings и рабочим столом. Сам код завершения не используется как единственное доказательство применения конкретной GPO.

## Настройка области применения

В ADMC на pc1 под доменным Administrator создано подразделение Lab-Computers; в нём показаны PC1 и PC2. В дереве политик E05-Lab-Desktop связана с этим подразделением. Опция связи «Отключено» снята; «Принудительно» также снята.

Блокировки пользовательского изменения задаются внутри настройки фона GPUI. Параметр «Принудительно» у связи GPO управляет наследованием политик и в этом опыте не включался.

Подтверждения: [подразделение](../evidence/10-10-2026/04-admc-lab-computers.png), [связь](../evidence/10-10-2026/05-admc-e05-gpo-link.png).

## Этап 1. Общий фон без блокировки

Через контекстное меню E05-Lab-Desktop → «Изменить…» открыт GPUI. Настройка находится в Компьютер → Административные шаблоны → Система ALT → Настройки GNOME → Внешний вид → Фон рабочего стола.

Состояние — «Включено». В оба поля для светлой и тёмной темы внесено:

```text
file:///usr/share/backgrounds/alt-gnome-desktop/alt-staraya-ladoga.jpg
```

Обе галочки «Блокировать настройку изображения…» сняты. Изменения сохранены кнопкой ОК, доступной внизу правой панели GPUI.

Из локальных административных учёток на каждом клиенте выполнено:

```bash
su -
gpupdate --target Computer --force
echo "gpupdate exit code: $?"
exit
```

На обоих клиентах получены сообщение Apply group policies for computer. и код 0. В сеансах student2 оба ключа возвращают Старую Ладогу, оба writable=true. По сообщению пользователя на pc1 фон сменился сразу; на pc2 понадобился перезапуск. Причина этой разницы отдельно не проверялась; связь с полными именами SSSD не установлена.

До включения блокировки пользователь на обоих клиентах изменил оба ключа на Эльбрус; фон сменился сразу. Применялись команды:

```bash
gsettings set org.gnome.desktop.background picture-uri "'file:///usr/share/backgrounds/alt-gnome-desktop/alt-elbrus.jpg'"
gsettings set org.gnome.desktop.background picture-uri-dark "'file:///usr/share/backgrounds/alt-gnome-desktop/alt-elbrus.jpg'"
```

Подтверждения: [настройка](../evidence/10-10-2026/06-gpui-e05-wallpaper-unlocked.png), [pc1](../evidence/10-10-2026/07-pc1-e05-wallpaper-applied.png), [pc2](../evidence/10-10-2026/08-pc2-e05-wallpaper-applied.png), [изменение на pc1](../evidence/10-10-2026/09-pc1-e05-wallpaper-user-change.png), [изменение на pc2](../evidence/10-10-2026/10-pc2-e05-wallpaper-user-change.png).

## Этап 2. Запрет изменения обеих тем

В той же машинной настройке включены обе галочки блокировки; пути к Старой Ладоге сохранены. После ОК на клиентах повторены gpupdate --target Computer --force, получены код 0 и новые сеансы после перезагрузки.

На обоих клиентах оба get возвращают Старую Ладогу, оба writable — false. Попытки установить Эльбрус для каждой темы завершаются сообщением «Ключ недоступен для записи»; на скриншотах фон остаётся Старой Ладогой. Это проверка запрета через GSettings, а не только состояния галочки в GPUI.

Подтверждения: [блокировки GPUI](../evidence/10-10-2026/11-gpui-e05-wallpaper-locked.png), [отказ pc1](../evidence/10-10-2026/12-pc1-e05-wallpaper-change-denied.png), [отказ pc2](../evidence/10-10-2026/13-pc2-e05-wallpaper-change-denied.png).

## Сопутствующее исправление времени

На скриншотах pc2 обнаружено отставание примерно на 19 минут. Проверка показала несинхронизированный Chrony на обоих клиентах: источник dc1 имеет ^? и Reach=0. Сам dc1 синхронизирован, но запрещает NTP-доступ обоим клиентам и не слушает UDP 123.

На dc1 разрешён доступ сети 10.77.0.0/24. Затем на клиентах перезапущен Chrony, выполнены burst 4/4 и makestep после выбора источника. Оба клиента выбрали dc1 (^*), получили Leap status=Normal; timedatectl позднее показала yes на обоих. Это исправление настройки стенда, а не самостоятельный эксперимент с новым номером.

Полный разбор — [time-synchronization.md](../docs/time-synchronization.md). До исправления часы pc2 нельзя использовать для общей хронологии; успешные проверки фона сами по себе не доказывали правильность времени.

## Этап 3. Снятие блокировки

В GPUI обе галочки сняты, состояние «Включено» и пути к Старой Ладоге сохранены. Скриншот содержит сообщение о применённых изменениях. После обновления и перезагрузки выполнены новые доменные входы; отдельный вывод gpupdate для этого этапа не передан, результат подтверждён сеансами.

Проверка                                             | pc1            | pc2
-----------------------------------------------------|----------------|---------------
Имя узла                                             | pc1.lab.test   | pc2.lab.test
TGT student2@LAB.TEST                                | Выдан 11:23:24 | Выдан 11:24:56
writable picture-uri                                 | true           | true
writable picture-uri-dark                            | true           | true
Изменение светлого фона                              | Успешно        | Успешно
Повторная запись тёмного фона без префикса нумерации | Успешно        | Успешно
Итог обоих ключей                                    | alt-elbrus.jpg | alt-elbrus.jpg

На промежуточных кадрах перед командой тёмной темы есть префикс «1.». Для подтверждения именно этой записи использован позднее переданный исправленный текст: команда выполнена без префикса, после неё прочитаны оба ключа. Отдельного изображения этих последних get не передано; сохранён текст.

## Вывод, текущее состояние и границы

**Часть E05 с обоями выполнена:** через одну компьютерную GPO управляются оба клиента; общий фон установлен, запрет проверен попытками записи, снятие запрета подтверждено для обеих тем. Работа сохраняется при различии формата доменных имён pc1 и pc2.

Политика E05-Lab-Desktop остаётся включённой и связанной с Lab-Computers; обе блокировки сняты. Машинный фон — Старая Ладога, пользовательские значения student2 — Эльбрус. Пользовательские настройки могут перекрывать машинное значение без блокировки; это соответствует описанному механизму ALT.

Проверена одна учётная запись student2, два клиента и два ключа фона в GNOME. Смена через графическое окно персонализации отдельно не записана; попытка обхода администратором не исследована. Удаление всей GPO или её связи, пользовательская GPO, фильтрация по группам и недоступность контроллера не проверены. Съёмные носители ещё не проверены: E05 в целом остаётся частично выполненным.

Итоговый снимок этапа — after-e05-wallpaper-2026-10-10 на трёх ВМ, учтённый по принятому порядку сохранения; восстановление не выполнялось. [Сведения о снимках](../evidence/10-10-2026/vm-snapshots.txt).
